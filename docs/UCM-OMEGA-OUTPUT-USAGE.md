# UCM-Ω：自适应输出恢复与 API 用量仪表盘

2026-11-08

## 1. 背景与根因

一个有效的 API Key、HTTP 200 和正常的“测试连接”都不保证模型返回了**完整的结构化推演结果**。UCM-Ω 需要模型在各段历史时窗输出因果事件、技术先决条件与事实记录，单次回复可能达到模型最大输出长度。截断的 JSON 通常无法解析；即便外观上是完整 JSON，如果服务商返回 `finish_reason: length`，仍有内容遗漏风险。

之前只进行一次格式化重试，极端情况下仍失败；而且历史窗口以固定大小生成，在模型无法容纳某个窗口的全部细节时没有继续拆分。

## 2. 分层恢复（未降低历史推演约束）

1. 每次结构化调用仍优先使用 JSON 模式。解析时检查顶层 JSON 对象、服务商 `finish_reason`；带截断标记的结果不被当作可靠完整输出。
2. 输出非 JSON 或截断时，进行一次带完整任务上下文的格式恢复；**不要求丢掉史事或输出空事件以图通过**，失败后保留具体错误。
3. UCM-Ω 接收到结构化输出失败，会把失败的历史时间窗**沿年份二分**，分别完成原有的地方性因果传播与核验。已成功完成的窗口不会因后续窗口失败被重复计算。
4. 如果已经压缩到单一年份仍然过长，再按区域拆为东南亚与太平洋、西亚中亚和非洲、欧洲、美洲与跨区域体系；还不够再按制度与冲突、科学技术经济、社会人口生态文化等领域拆分。每一部分仍然使用原有世界线和此前已审查的事实作为输入。
5. 各个部分通过 `auditBatch` 检查；审计合格的事件与知识统一加入同一世界线，不再因每段大事排行榜的九个展示名额而直接丢失其他合格节点。显著性筛选只生成 `salient` 标记。
6. 全部时段结束后，针对整条世界线的所有事件、知识、跨窗口因果引用和时间互斥再进行 `auditBatch` 一致性检查。不通过则不提交世界线，避免半成品被误存为完整历史。

### 边界

推演质量取决于模型的历史知识、对干预因果关系的理解以及提供的史料，**没有机制能严格保证历史预测质量不变或绝对真实**。分片能解除单次 JSON 过长这一工程性瓶颈，但需要更多 API 调用、时间和费用。分片次数有限制，以避免不可控开销；如果一个最小范围仍无法完整生成，会明确失败而不是隐式返回空历史。现在是“本轮任务内细分并保留已成功部分”的方式，**不提供跨页面刷新或浏览器崩溃的持久断点续算**。

## 3. 设置中的 Token 和费用仪表盘

打开“设置”即可看到“用量与费用”。本版本启用后，每个从浏览器发出的模型 API 请求，包括重试、连接测试、成功和错误返回，都会在浏览器本地生成精简用量记录。统计涵盖文本模型与图像 API 请求。

统计依据：

- `usage.prompt_tokens` / `usage.input_tokens`：服务商报告的输入 Token。
- `usage.completion_tokens` / `usage.output_tokens`：服务商报告的输出 Token。
- 服务商可选的缓存输入、推理输出、总 Token 和 `usage.cost`：只在对应字段存在时登记。
- 完全没有返回 `usage` 的调用仍统计次数，但不猜测 Token 数。
- 如果服务商回传费用，就显示**服务商报告费用**；如果未回传成本，而 Token 数可用，可以在设置中为**当前服务商 + 模型**手动输入每百万输入/输出 Token 的 USD 单价，计算**可统计部分的估算费用**。每个模型的费率独立存储，默认未知，绝不凭模型名字猜测价格。
- 数据仅保存在当前浏览器的 `localStorage`，与世界线数据和连接密钥独立；可单独清除用量，不影响世界线。不会保存 API Key、完整请求提示词或模型回答。其他设备的消费与本功能上线前的调用不包含在内。

**仪表盘不是服务商官方账单。** 即使返回 Token，仍可能有额外计费项、图像价格、缓存优惠、订阅折扣、重试成本或非 USD 计费。应以对应 API 服务商的正式账单和价格文档为准。
