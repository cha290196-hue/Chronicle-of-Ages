# 演算中枢：持续探索与知识生长

2026-11-08。适用于《岁月史书》UCM-Ω 浏览器版。

## 1. 基本哲学

首次历史干预建立的是整条替代地球世界线的宏观状态，不是一本细节已经穷尽的史书。用户随后向演算中枢提出的问题，不是对固定列表的全文检索，而是对同一既定世界线的一次**局部深度推演**，例如 1850 年某地普通居民的实际生活、某项技术的产业链或一个人物的生平。

“尚未记录”不等于“从未发生”；“模型刚提出”也**不等于**“确定发生”。本功能保存有价值且通过程序形式约束的**推演知识候选**，保留推演来源和不确定性。无历史根据时要坦率标明假设，绝不把反事实推演写进不可变现实 A 史实层。

## 2. 每次问答的实际计算流程

1. 根据当前世界线 ID、父分支和分叉时间，检索该世界已有的历史事件、知识记录与相关对话；不自动把另一个平行世界的材料视为本世界事实。
2. 第一轮模型调用进行**针对问题的局部历史状态推演**，内部产生回答草稿以及原子事实候选（人物、地理、机构、科技、社会生活等）；不要求每个回答必须新建知识。
3. 程序逐项核验候选的历史年份、时间跨度、有效来源引用、说明依据及既有事实的重复或显式互斥。没有可信支持、违反年代规则、明显重复或正面冲突的候选不入库。此层并不能证明新发现的真伪。
4. 第二轮模型调用将既有历史状态、已通过检查的候选与未解决的疑问整合为自然回答；**用户可见的文字不要求特定排版模板**。
5. 仅在成功取得回答之后，知识记录与对话同时提交到本地世界线状态。新知识可以出现在知识库的记录栏、下次问答的检索上下文中，也可作为未来子分支推演的先验条件。

### 数据分层

- **现实 A 的记录事件**：只读，绝不因模型输出而修改。
- **分支原有推演事件与基础事实**：宏观历史框架，不因问答而无声改写。
- **演算中枢的新增推演知识**：保存在所属世界线的 `knowledge` 列表，含 `firstYear`、`validUntil`、`entity`、`attribute`、`value`、`basis`、`evidenceIds`、`status: hypothesis`、`source: core-exploration` 和不确定性标注。
- **基线 A 的问答补充**：另存为 `baselineKnowledge` 的推测性研究备注，不改写 A 线的 `BASELINE`。
- **自然对话**：原有 `chats` 仍保存每次问答，但不是所有自然语言句子都会自动成为历史事实。

### 分支知识继承

创建 B 的子分支 C 时，C 在新分叉点之前继承 B 的历史及已沉淀知识；**晚于 C 分叉点才发生的 B 事实不得进入 C**。父分支在 C 创建后又补充了“发生于 C 分叉以前”的知识，则 C 的知识检索也会更新，但不会将父分支在更晚年份的知识泄漏给 C。

### 例子

第一次修改：“明朝没有灭亡而延续至近代”，形成 B 的宏观全球演化。之后询问 B：“1850 年法国普通家庭如何生活？”演算中枢以 B 的欧洲及全球经济、科学、人口和社会状态为条件，提出局部社会历史推论。符合检查要求的新知识会进入 B 的知识库；下一次询问法国贸易或工业时，可以检索这些记录，无须逐字重复原来回答。如果模型只重复知识库中已存在的事实，就不重复创建条目。

## 3. 精确边界

这个版本运行的是 **LLM 驱动的局部反事实情景推理 + 程序化一致性约束**。它不是已经校准了全球千年历史的数值预测器，更不能保证“全知全能”。形式化检查能识别年代、ID、重复和部分矛盾，却不能替代史学证据或专家核查。程序不把模型自述的“置信度”解释为真实的历史概率。

用户每问一次会追加模型调用，约 **两次 LLM 请求**（结构化推演、自然回答），在源模型输出格式不满足要求或网络异常时可能无法生成知识。新增知识使用项目现有 `localStorage` 和世界线 JSON 归档；这沿用了现有大小上限，将来若长时间积累大量信息，需移至 IndexedDB，避免浏览器存储配额不足。

## 4. 测试与覆盖范围

`tests/exploration-knowledge.test.mjs` 验证连续问答的上下文增量、事实去重与互斥、日期校验、历史记录不变、父子分支按时间继承、存档恢复和实际网页问答调用路径。测试使用模拟模型接口，不代表全球史实正确性检验，也未以真实用户付费 API 密钥进行线上对话。

设计原则：**一次干预创造宏观世界，一次问答深化局部世界，知识层生长而因果框架不漂移。**
